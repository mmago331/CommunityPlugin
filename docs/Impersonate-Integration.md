# Adding an "Impersonate User" Menu Item to Encompass — Exhaustive Rebuild Guide

This document is a **build-from-scratch specification** for a single
Encompass SDK plugin feature: a custom "Impersonate" menu item that
appears under a new dropdown on Encompass's top menu bar, opens a
WinForms dialog where a Super Admin types a username, calls
Encompass's `ImpersonateUser` API, and refreshes the pipeline so the
UI reflects the impersonated user.

It is intentionally thorough: every type, every assembly, every
control on the dialog, every API call, every event registration, and
every gotcha is written out explicitly. If you follow this document
end-to-end and a step does not work, the discrepancy is the bug —
there is no implicit knowledge required beyond what is written here.

## 1. What the feature is and what the user sees

### 1.1 The user-facing behavior

1. Encompass starts, the user logs in.
2. A new dropdown labeled **"Community Menu"** appears under the
   File menu (the first item on the main menu strip).
3. Under that dropdown there is an entry labeled **"Impersonate"**.
   (And any number of other items the plugin defines — each is a
   `MenuItemBase` subclass picked up automatically by reflection.)
4. Clicking **Impersonate** opens a small WinForms dialog with:
   - A **textbox** for the username.
   - A **listbox** of matching enabled users that updates live as
     the textbox text changes.
   - An **Impersonate** button: calls
     `Session.ImpersonateUser(<username>)`, invalidates the cached
     user info, and refreshes the pipeline so the impersonated
     user's view is shown.
   - A **Return to Myself** button: calls `Session.RestoreIdentity()`
     and refreshes the pipeline back to the real user.
5. Only Super Admins (or users granted access via the optional
   permission gate in §12 of the framework section) see the menu.

### 1.2 Why a plugin and not Encompass's built-in admin tools?

Encompass's stock "Impersonate" lives under Admin Tools and is a
heavier workflow. This plugin gives an in-client Super-Admin
shortcut without leaving the loan client. The same TopMenu
infrastructure can host any number of additional shortcuts (a
"Settings Extract" item is a common companion).

```

        │   └──────────────────────────────┘                   │
        │                                                      │
        │   TextChanged   → repopulate listbox from            │
        │                   EncompassApplication.Session       │
```

the `[Plugin]` attribute. Discovery is `Assembly.GetTypes()` with
`type.IsSubclassOf(typeof(Plugin))` and
`type.IsSubclassOf(typeof(MenuItemBase))` filters.

## 4. End-to-end runtime trace

This is what happens, in order, on the very first run after Encompass
starts. Read this if anything in §9–§14 is unclear.

1. **Encompass start.** The client scans its plugin path
   (`%AppData%\Encompass\Plugins` or the central deployment location)
   for any assembly containing a type marked with the `[Plugin]`
   attribute from `EllieMae.Encompass.ComponentModel`.
2. **`PluginEntry` instantiated.** Encompass calls its parameterless
   ctor, which calls `Plugins.Start()`.
3. **`Plugins.Start()` discovers plugin classes.** It reflects on
   the executing assembly:
   ```csharp
   foreach (Type t in assembly.GetTypes()
                              .Where(t => t.IsSubclassOf(typeof(Plugin))))
       (Activator.CreateInstance(t) as Plugin).Run();
   ```
   `TopMenuBase` is one of those subclasses.
4. **`TopMenuBase.Run()`** (inherited from `Plugin`) inspects which
   marker interfaces it implements. It implements `ILogin`, so
   `Plugin.Run()` subscribes:
   ```csharp
   EncompassApplication.Login -= Base_Login;
   EncompassApplication.Login += Base_Login;
   ```
5. **User logs in.** Encompass raises
   `EncompassApplication.Login`. The base class calls
   `TopMenuBase.Login(sender, e)`.
6. **`TopMenuBase.Login` body.**
   - `GradientMenuStrip menu = (GradientMenuStrip)FormWrapper.Find("mainMenu");`
     — finds Encompass's main `MenuStrip` (it is a custom
     `GradientMenuStrip` from `EllieMae.EMLite.UI`) by control name.
   - `ToolStripMenuItem communityMenu = new ToolStripMenuItem("Community Menu");`
   - `ToolStripMenuItem item = menu.Items[0] as ToolStripMenuItem;`
     — index 0 is the File menu.
   - `item.DropDownItems.Add(communityMenu);` — the new dropdown is
     added as a **submenu of File**, not at the top level.
   - `communityMenu.DropDownItems.AddRange(GetDropDownItems());`
7. **`GetDropDownItems()`** reflects on the assembly:
   ```csharp
   foreach (Type type in assembly.GetTypes()
                                 .Where(t => t.IsSubclassOf(typeof(MenuItemBase))))
   {
       MenuItemBase mi = Activator.CreateInstance(type) as MenuItemBase;
       if (mi != null && mi.CanRun()
           && active.FirstOrDefault(x => x.GetType() == mi.GetType()) == null)
           active.Add(mi.CreateToolStripMenu(null, mi.GetType().Name));
   }
   return active.ToArray();
   ```
   For each `MenuItemBase` subclass:
   - Instantiate.
   - If `CanRun()` returns true and no item of that runtime type
     is already in the list, call `CreateToolStripMenu(null, "Impersonate")`
     and add it.
8. **`MenuItemBase.CreateToolStripMenu`** builds a `ToolStripMenuItem`
   with the given name and wires `Click → menuItem_Click`.
9. **User opens the dropdown and clicks Impersonate.**
10. **`Impersonate.menuItem_Click`** runs:
    ```csharp
    Impersonate_Form form = new Impersonate_Form();
    form.Show();   // modeless
    ```
11. **`Impersonate_Form`** is a normal `System.Windows.Forms.Form`.
    Its ctor calls `InitializeComponent()` (Designer-generated layout
    of textbox, listbox, two buttons). The form is shown modeless.
12. **User types in `txtUser`.** `TxtUser_TextChanged` fires:
    - `lbResults.Items.Clear();`
    - `lbResults.Items.AddRange(`
      `EncompassApplication.Session.Users.GetAllUsers()`
      `.Cast<User>()`
      `.Where(x => x.Enabled && x.ID.Contains(user))`
      `.Select(x => x.ID).ToArray());`
13. **User clicks Impersonate** with `txtUser.Text` set to a username:
    ```csharp
    EncompassHelper.SessionObjects.Session.ImpersonateUser(user);
    EncompassHelper.SessionObjects.InvalidateUserInfo();
    RefreshPipeline();
    ```
14. **`RefreshPipeline()`** forces Encompass's main UI to repaint
    against the impersonated identity:
    ```csharp
    MainScreen mainScreen = FormWrapper.Find("mainScreen") as MainScreen;
    mainScreen.PipelineScreenBrowser = null;
    IPipeline pipeline = mainScreen.GetService<EllieMae.EMLite.Common.UI.IPipeline>();
    mainScreen.ShowTab("Home");
    mainScreen.ShowTab("Pipeline");
    ```
15. **User clicks Return to Myself.**
    ```csharp
    EncompassHelper.SessionObjects.Session.RestoreIdentity();
    RefreshPipeline();
    ```
    The original user identity is restored and the pipeline reloads.

### 5.6 The `Session` namespace ambiguity (read this once)

There are **two** classes named `Session` in this tree:

- `EllieMae.EMLite.RemotingServices.Session` — **static** class with
  `DefaultInstance`, `SessionObjects`, etc.
- `EllieMae.EMLite.RemotingServices.Sessions.Session` — the
  **instance** type the static accessor returns. This is the type
  with `ImpersonateUser` and `RestoreIdentity` on it.

`EncompassHelper.SessionObjects.Session` returns the **instance**
type via the path `Session.DefaultInstance.SessionObjects.Session`.

There is also `EncompassApplication.Session` (the **automation**
session, a different object from `EncompassObjects.dll`). It is what
exposes `Session.Users.GetAllUsers()`. The dialog uses both —
`EncompassApplication.Session.Users` for enumeration and
`SessionObjects.Session.ImpersonateUser` for the action.

## 6. Project scaffolding from zero

### 6.1 Target framework

- **.NET Framework 4.7.2** for Encompass 19.x and later. Older
  Encompass versions (≤19.3) used 4.6.1; pick the framework that
  matches the Encompass DLLs on the dev machine (see §6.3).
- `OutputType` must be `Library` (DLL).
- `AssemblyName` and `ProjectGuid` can be anything — Encompass
  identifies plugins by the `[Plugin]` attribute, not by name.

### 6.2 Minimal `.csproj` shape

```xml
<Project ToolsVersion="15.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <Import Project="$(MSBuildExtensionsPath)\$(MSBuildToolsVersion)\Microsoft.Common.props"
          Condition="Exists('$(MSBuildExtensionsPath)\$(MSBuildToolsVersion)\Microsoft.Common.props')" />
  <PropertyGroup>
    <Configuration Condition=" '$(Configuration)' == '' ">Debug</Configuration>
    <Platform Condition=" '$(Platform)' == '' ">AnyCPU</Platform>
    <ProjectGuid>{NEW-GUID-HERE}</ProjectGuid>
    <OutputType>Library</OutputType>
    <RootNamespace>MyPlugin</RootNamespace>
    <AssemblyName>MyPlugin</AssemblyName>
    <TargetFrameworkVersion>v4.7.2</TargetFrameworkVersion>
    <Deterministic>false</Deterministic>
  </PropertyGroup>
  <!-- references below -->
</Project>
```

The legacy (`Microsoft.NET.Framework`) and SDK-style
(`<Project Sdk="Microsoft.NET.Sdk">`) schemas both build
identically; either is fine.

### 6.3 Where to find the Encompass DLLs

On a developer machine that has run Encompass at least once, the
DLLs are deployed by ClickOnce under:

```
%LocalAppData%\Apps\2.0\<hash>\...\SmartClientCache\Apps\UAC\Ellie Mae\<opaque-hash>=\Encompass360\
```

A typical relative `<HintPath>` from a project file looks like:

```
..\..\..\..\..\..\SmartClientCache\Apps\UAC\Ellie Mae\<opaque-hash>=\Encompass360\<dll>
```

Easier in practice: copy the required DLLs into a `lib/` folder
inside your repo and reference from there. Do **not** check the
DLLs into source control unless your license allows it.

### 6.4 References required for *this feature only*

```xml
<ItemGroup>
  <Reference Include="EncompassObjects">    <HintPath>...\EncompassObjects.dll</HintPath>    <Private>False</Private></Reference>
  <Reference Include="EncompassAutomation"> <HintPath>...\EncompassAutomation.dll</HintPath> <Private>False</Private></Reference>
  <Reference Include="ClientSession">       <HintPath>...\ClientSession.dll</HintPath>       <Private>False</Private></Reference>
  <Reference Include="ClientCommon">        <HintPath>...\ClientCommon.dll</HintPath>        <Private>False</Private></Reference>
  <Reference Include="MainUI">              <HintPath>...\MainUI.dll</HintPath>              <Private>False</Private></Reference>
  <Reference Include="Client">              <HintPath>...\Client.dll</HintPath>              <Private>False</Private></Reference>

  <Reference Include="System" />
  <Reference Include="System.Core" />
  <Reference Include="System.Drawing" />
  <Reference Include="System.Windows.Forms" />
</ItemGroup>
```

**`<Private>False</Private>` (i.e. `Copy Local = False`) is
mandatory** on every Encompass reference. Encompass loads these
DLLs itself at runtime; if a second copy is in the plugin folder
the runtime resolves to the wrong CLR type and the
`(MainScreen)Find("mainScreen")` cast (or any other internal-type
cast) will silently fail.

## 7. The plugin entry point and discovery boot

### 7.1 `PluginEntry.cs`

```csharp
using EllieMae.Encompass.ComponentModel;

namespace MyPlugin
{
    [Plugin]
    public class PluginEntry
    {
        public PluginEntry()
        {
            Plugins.Start();
        }
    }
}
```

Encompass scans every loaded assembly for any class marked
`[Plugin]`. It instantiates each such class once per client session,
using its **public parameterless** ctor. Putting your bootstrap in
the ctor body is the standard pattern.

### 7.2 `Plugins.cs`

```csharp
using System;
using MyPlugin.Objects.Interface;

namespace MyPlugin.Objects
{
    public static class Plugins
    {
        public static void Start()
        {
            var i = new InterfaceHelper();
            foreach (Type type in i.GetAll(typeof(Plugin)))
                (Activator.CreateInstance(type) as Plugin).Run();
        }
    }
}
```

### 7.3 `InterfaceHelper.cs`

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

namespace MyPlugin.Objects.Interface
{
    public class InterfaceHelper
    {
        public List<Type> GetAll(Type baseType)
        {
            try
            {
                return this.GetType().Assembly
                          .GetTypes()
                          .Where(t => t.IsSubclassOf(baseType))
                          .ToList();
            }
            catch (Exception ex)
            {
                Logger.HandleError(ex, nameof(InterfaceHelper));
                return null;
            }
        }
    }
}
```

## 8. The Plugin base class and `ILogin` marker

### 8.1 Marker interfaces

```csharp
namespace MyPlugin.Objects.Interface
{
    public interface IPlugin       { void Run(); }
    public interface ILogin        { void Login(object s, System.EventArgs e); }
    public interface IMenuItemBase {
        System.Windows.Forms.ToolStripItem CreateToolStripMenu(
            System.Drawing.Image image, string name);
    }
}
```

### 8.2 `Plugin.cs` — only the slice this feature needs

```csharp
using EllieMae.Encompass.Automation;
using MyPlugin.Objects.Interface;
using System;

namespace MyPlugin.Objects
{
    public abstract class Plugin : IPlugin
    {
        public abstract bool Authorized();

        public virtual void Run()
        {
            if (!Authorized()) return;

            if (typeof(ILogin).IsAssignableFrom(GetType()))
            {
                EncompassApplication.Login -= Base_Login;
                EncompassApplication.Login += Base_Login;
            }
        }

        public virtual void Login(object sender, EventArgs e) { }

        private void Base_Login(object sender, EventArgs e)
        {
            try { Login(sender, e); }
            catch (Exception ex) { Logger.HandleError(ex, nameof(Base_Login)); }
        }
    }
}
```

Design choices encoded above:

- **`-=` always precedes `+=`.** Encompass may raise `Login` more
  than once in some edge cases (re-auth, re-bind). Unsubscribing
  first prevents duplicate handlers and therefore duplicate
  "Community Menu" entries on the main menu.
- **`Authorized()` is a kill switch.** Subclass returns `false` to
  disable itself; `Run()` short-circuits before subscribing.

### 8.3 `Logger.cs`

```csharp
using EllieMae.Encompass.Client;
using System;

namespace MyPlugin.Objects
{
    public static class Logger
    {
        public static void HandleError(Exception ex, string name, object data = null)
        {
            try
            {
                if (string.IsNullOrEmpty(name)) return;
                ApplicationLog.WriteError("MyPlugin",
                    $"{name}{Environment.NewLine}{ex}");
            }
            catch { /* swallow */ }
        }
    }
}
```

`ApplicationLog` lives in `EllieMae.Encompass.Client` (the `Client.dll`
reference). Errors written here show up in Encompass's standard

## 9. The TopMenu integration — `TopMenuBase`, line-by-line

```csharp
using EllieMae.EMLite.UI;                  // GradientMenuStrip
using MyPlugin.Objects;
using MyPlugin.Objects.Interface;
using System;
using System.Collections.Generic;
using System.Drawing;
using System.Linq;
using System.Windows.Forms;

namespace MyPlugin.TopMenu
{
    public class TopMenuBase : Plugin, ILogin
    {
        private List<ToolStripItem> active;

        public override bool Authorized() => true; // or wire to your permission gate

        public override void Login(object sender, EventArgs e)
        {
            GradientMenuStrip menu = (GradientMenuStrip)FormWrapper.Find("mainMenu");
            ToolStripMenuItem communityMenu = new ToolStripMenuItem("Community Menu");
            ToolStripMenuItem item = menu.Items[0] as ToolStripMenuItem;
            item.DropDownItems.Add(communityMenu);
            communityMenu.DropDownItems.AddRange(GetDropDownItems());
        }

        private ToolStripItem[] GetDropDownItems()
        {
            active = new List<ToolStripItem>();
            foreach (Type type in this.GetType().Assembly.GetTypes()
                                     .Where(t => t.IsSubclassOf(typeof(MenuItemBase)))
                                     .ToList())
            {
                try
                {
                    MenuItemBase mi = Activator.CreateInstance(type) as MenuItemBase;
                    if (mi != null
                        && mi.CanRun()
                        && active.FirstOrDefault(x => x.GetType() == mi.GetType()) == null)
                    {
                        active.Add(mi.CreateToolStripMenu(null, mi.GetType().Name));
                    }
                }
                catch (Exception ex)
                {
                    Logger.HandleError(ex, nameof(TopMenuBase));
                }
            }
            return active.ToArray();
        }
    }
}
```

### 9.1 Why `Login` is the trigger

The main menu (`mainMenu`) only exists after the shell window is
constructed, and the shell is only constructed after the user
authenticates. Subscribing to `LoanOpened` would be too late on
some flows (the menu must appear before any loan is opened). The
`Login` event fires once per session, immediately after the shell
is ready.

### 9.2 The two-level menu placement

```
menu.Items[0]                         ← the "File" menu
    .DropDownItems
        .Add(communityMenu)           ← "Community Menu" is added INSIDE File
            .DropDownItems
                .AddRange(...)         ← each MenuItemBase is INSIDE Community Menu
```

If you want a **top-level** entry next to "File", "Encompass", "Loan",
etc. instead, replace:

```csharp
ToolStripMenuItem item = menu.Items[0] as ToolStripMenuItem;
item.DropDownItems.Add(communityMenu);
```

with:

```csharp
menu.Items.Add(communityMenu);
```

The reference puts it under File so the new dropdown is visually
discoverable without taking up scarce top-bar real estate.

### 9.3 The `GradientMenuStrip` cast

`menu.Items[0]` returns `ToolStripItem`; the cast `as ToolStripMenuItem`
yields the first menu (File). If you ever see a `NullReferenceException`
here, Encompass has changed its main menu structure — fall back to
finding the menu by `Text`:

```csharp
var item = menu.Items.OfType<ToolStripMenuItem>()
              .FirstOrDefault(x => x.Text.StartsWith("&File") || x.Text == "File");
```

### 9.4 Why reflect on `MenuItemBase` subclasses

Reflection-driven discovery means **adding a new menu item is a
single new file** that subclasses `MenuItemBase` and implements
`CanRun()` + `menuItem_Click`. No central registration list to
edit. The de-dup check `active.FirstOrDefault(...) == null`
guards against `Login` firing more than once.

### 9.5 The menu item's label

```csharp
mi.CreateToolStripMenu(null, mi.GetType().Name)
```

The label shown to the user is the **C# class name** of the
`MenuItemBase` subclass. So `class Impersonate : MenuItemBase`
appears as the text **"Impersonate"** in the dropdown. If you
want a different label, override `CreateToolStripMenu` in your
subclass or extend `MenuItemBase` to expose a `DisplayName`
property.

## 10. The MenuItemBase abstract class

```csharp
using MyPlugin.Objects.Interface;
using System;
using System.Drawing;
using System.Windows.Forms;

namespace MyPlugin.TopMenu
{
    public abstract class MenuItemBase : IMenuItemBase
    {
        internal ToolStripMenuItem menuItem;

        public abstract bool CanRun();

        public ToolStripItem CreateToolStripMenu(Image image, string Name)
        {
            menuItem = new ToolStripMenuItem(Name);
            menuItem.Image = image;
            menuItem.Click += new EventHandler(menuItem_Click);
            return menuItem;
        }

        protected abstract void menuItem_Click(object sender, EventArgs e);
    }
}
```

Per-member notes:

- **`internal ToolStripMenuItem menuItem;`** — kept as a field so a
  subclass could later mutate the visible item (toggle `Enabled`,
  change `Text`, etc.). The default flow does not use it after
  construction.
- **`CanRun()`** is abstract — every subclass must answer "should I
  appear in the menu?" The reference uses `PluginAccess.CheckAccess(nameof(X))`;
  the minimum-viable rebuild uses `EncompassHelper.IsSuper` directly.
- **`CreateToolStripMenu(Image, string)`** is called by `TopMenuBase`
  with `(null, classname)`. The `image` parameter exists so future
  subclasses can show an icon next to the label.
- **`menuItem_Click`** is the only `protected abstract` method — the
  one thing a subclass must implement.

## 13. The impersonation API calls

### 13.1 Searching users live

```csharp
lbResults.Items.AddRange(
    EncompassApplication.Session.Users.GetAllUsers()
        .Cast<User>()
        .Where(x => x.Enabled && x.ID.Contains(user))
        .Select(x => x.ID)
        .ToArray());
```

- `EncompassApplication.Session.Users` is the automation `Users`
  collection. `GetAllUsers()` returns every user in the
  organization (enabled and disabled). The `.Enabled` filter
  removes disabled accounts.
- `x.ID` is the user's **login ID**, not their display name. This
  is what `ImpersonateUser` expects.
- `x.ID.Contains(user)` is a **case-sensitive substring** match. If
  you want case-insensitive, use
  `x.ID.IndexOf(user, StringComparison.OrdinalIgnoreCase) >= 0`.
- Empty `user` matches every enabled user — that is intentional
  (acts as a "list all" when the textbox is empty).

### 13.2 The impersonation call

```csharp
EncompassHelper.SessionObjects.Session.ImpersonateUser(user);
EncompassHelper.SessionObjects.InvalidateUserInfo();
```

- `EncompassHelper.SessionObjects` resolves to
  `Session.DefaultInstance.SessionObjects` (the
  `EllieMae.EMLite.RemotingServices.Session` static accessor).
- `SessionObjects.Session.ImpersonateUser(string)` is the internal
  client-server method that swaps the auth token for the given
  user. It **does not** repaint the UI — that is what the next two
  steps do.
- `SessionObjects.InvalidateUserInfo()` clears the cached `User`
  object so the next access (e.g. by the pipeline) fetches the
  impersonated user's data instead of the original.

### 13.3 Restoring identity

```csharp
EncompassHelper.SessionObjects.Session.RestoreIdentity();
```

This undoes a prior `ImpersonateUser`. Calling it when not
impersonating is safe but a no-op.

### 13.4 Required permission

`ImpersonateUser` is **only callable by a Super Admin**. If you
call it as a regular user the server rejects the call. That is why
`CanRun()` in the menu item gates visibility on
`EncompassHelper.IsSuper`.

## 14. The pipeline-refresh trick

After swapping identity, the loaded pipeline still shows the
original user's results. The reference's refresh sequence:

```csharp
MainScreen mainScreen = FormWrapper.Find("mainScreen") as MainScreen;
mainScreen.PipelineScreenBrowser = null;
IPipeline pipeline = mainScreen.GetService<EllieMae.EMLite.Common.UI.IPipeline>();
mainScreen.ShowTab("Home");
mainScreen.ShowTab("Pipeline");
```

What each line does:

- **`Find("mainScreen")`** — the shell window's top-level
  `Controls` collection contains a `MainScreen` named
  `"mainScreen"`. The cast `as MainScreen` requires
  `using EllieMae.EMLite.MainUI;`.
- **`PipelineScreenBrowser = null;`** — nulls the cached pipeline
  browser instance. The next time the Pipeline tab is shown, the
  shell rebuilds it from scratch against the current (now
  impersonated) identity.
- **`GetService<IPipeline>()`** — purely defensive. The local
  `pipeline` variable is never used in the reference; touching the
  service ensures the IoC container is initialized in case the
  pipeline rebuild needs it. You can omit this line in a clean
  rewrite.
- **`ShowTab("Home")` → `ShowTab("Pipeline")`** — bouncing through
  Home first forces the Pipeline tab to redraw on re-entry. A
  direct `ShowTab("Pipeline")` while already on Pipeline is a
  no-op; the bounce defeats that.

The two valid tab names used here are exactly **`"Home"`** and
**`"Pipeline"`** (case-sensitive).

## 18. Gotchas — every one of them

### 18.1 Assembly resolution

- **`Copy Local = False` on every Encompass reference.** Mandatory.
  Symptom of getting this wrong: the `as MainScreen` or
  `as GradientMenuStrip` cast returns `null` despite the control
  obviously being the right type.
- **Don't reference `mscorlib` or `System` manually** — the
  framework reference brings them.

### 18.2 Timing

- **Subscribe on `Login`, not `LoanOpened`.** `mainMenu` exists
  before any loan opens. Hooking `LoanOpened` is too late on the
  first-paint frame and the user briefly sees a menu without your
  dropdown.
- **`mainMenu` is a `GradientMenuStrip`, not a stock `MenuStrip`.**
  The cast must be to `GradientMenuStrip` (from
  `EllieMae.EMLite.UI`, in `MainUI.dll`). A bare `MenuStrip` cast
  also works because `GradientMenuStrip` inherits from `MenuStrip`,
  but the stricter cast catches Encompass replacing the menu
  control in a future version.

### 18.3 Reflection-driven menu population

- **`Login` can fire more than once** in re-auth flows. The
  reference de-dupes by runtime type:
  `active.FirstOrDefault(x => x.GetType() == mi.GetType()) == null`.
  Without this, Login number 2 doubles every menu entry.
- **Plugin discovery requires a public parameterless ctor** on
  every `MenuItemBase` subclass. The instantiation is via
  `Activator.CreateInstance(type)`.

### 18.4 The two `Session` types

- `EllieMae.EMLite.RemotingServices.Session` (static, has
  `DefaultInstance` and `SessionObjects`).
- `EllieMae.EMLite.RemotingServices.Sessions.Session` (instance,
  has `ImpersonateUser` and `RestoreIdentity`).
- `EncompassApplication.Session` (automation wrapper, has `Users`).

All three appear in the dialog code. Read using directives
carefully when porting code or you will get phantom compile errors.

### 18.5 `ImpersonateUser` is super-admin only

- A non-Super-Admin call throws on the server. The client-side
  `ImpersonateUser` does not pre-validate.
- Gate menu visibility via `CanRun()` *and* server-side permissions
  — the server is the source of truth.
- If you do invoke as a non-Super-Admin, wrap the call in
  `try/catch` and surface a meaningful error.

### 18.6 `InvalidateUserInfo` is mandatory

- Without `InvalidateUserInfo()`, the **pipeline still shows the
  original user's filters** because Encompass caches the user
  object in `SessionObjects`. The pipeline refresh sequence alone
  is not enough.

### 18.7 Pipeline refresh

- **The bounce through `"Home"` is intentional.** A direct
  `ShowTab("Pipeline")` while already on Pipeline is a no-op;
  bouncing through Home forces a redraw.
- If the user is currently inside a loan (Loan tab focused), the
  `ShowTab` bounce will discard their loan view. The reference
  ignores this — for most workflows it's fine because impersonation
  is rare and intentional. If you want to preserve loan focus, cache
  the current tab name before the bounce and restore it after.

### 18.8 Live search performance

- `GetAllUsers()` returns every user. For tenants with thousands of
  users this can be slow. The reference re-fetches on every
  keystroke. If perf matters, cache the user list once when the
  form opens and filter the cached array in `TxtUser_TextChanged`.

### 18.9 Modal vs. modeless

- The reference uses `form.Show()` (modeless). The user can switch
  away while impersonating and the dialog stays open. If you want
  to lock attention, use `form.ShowDialog()` instead — but then
  pipeline refresh happens behind the dialog and the user can't see
  the effect until they close it.

### 18.10 `FormWrapper.Find` returns null on startup races

- If `EncompassApplication.Login` fires before the shell finishes
  building its control tree (rare but observed during very fast
  cold starts), `Controls.Find("mainMenu", true)` returns an empty
  array and the cast crashes. The minimum-viable rebuild guards
  against this with a `null` check; the reference does not, on
  the assumption that the timing is reliable in practice. Add
  the null check if you want belt-and-braces.

### 18.11 The dialog's `Form.Text` is "Impersonate_Form"

The Designer-generated `this.Text = "Impersonate_Form";` leaks the
class name into the title bar. Override it in the code-behind ctor:

```csharp
public Impersonate_Form()
{
    InitializeComponent();
    this.Text = "Impersonate User";   // friendlier title
}
```

The reference leaves it as the class name.

### 18.12 Plugin discovery

- `[Plugin]` class must have a **public, parameterless** ctor.
- The `[Plugin]` class is instantiated **once per client process**.
  Don't do per-loan work in its ctor.
